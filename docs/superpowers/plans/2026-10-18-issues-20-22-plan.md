## Part A: #22

**A1. First-turn timer.** Confirmed cause: `auto_advance` deals and enters `player_turn` straight
away, and `check_and_start_turn_timer` starts the clock while clients still show
`ShareSuspendOverlay` (graph travel 3.2s + 5s countdown + any swap animations).
- Server: `Room.day_start_pending` (set of player ids | None). Set to the connected players when
  `auto_advance` deals day ≥ 2. `check_and_start_turn_timer` defers while it's non-empty and
  arms a 20s fallback task that clears it. New action `day_start_ready` removes the sender.
  Disconnects are dropped from the pending set.
- Client: `GameBoard.handleSuspendComplete` sends `day_start_ready`. Add it to the
  `ClientMessage` union and to the "don't queue while offline" list.

**A2. Share suspend.** In `ShareSuspendOverlay`, a row tap selects. A sticky footer holds
`Halt <Company>` (disabled until selected) and `Pass`. Selectable rows get an amber/radio look
distinct from the price grid. `ShareSuspendModal.tsx` is unused, so delete it.

**A3. Rights Issue pass confirm.** In `RightsIssueModal`, Pass shows an inline "Pass on N
discounted shares?" confirm when `maxQty > 0`.

**A4. Trade popup.** In `TradeModal`, Max and RI go on their own 2-column row (44px on mobile).
Add a `TurnTimerDisplay` to the header.

## Part B: #20

**Engine**
- `GameState(num_players, player_ids=None)`: room ids can be non-contiguous after lobby
  leave/kick, so the engine must use the real room ids.
- `Player.left` flag, serialised. New `leave_game(gs, pid)` in `phases.py` (or a new
  `engine/leave.py`): return shares to the pool, cash = 0, clear the hand, mark left, recompute
  positions for every company, remove from all queues (finalising sub-phases if a queue empties),
  fix up `current_turn` if it's their turn, end the game if ≤1 active player remains.
- `advance_turn`: skip left players. Rights issue order, CD queue and suspend queue skip left
  players. `complete_card_reveal` counts active players. `deal_cards` gives no hand to left players.

**Server / room**
- `add_player`: in the lobby, reject a name that belongs to a connected player
  (`{"type":"error","code":"name_taken"}`). Left players (`room.left_ids`) can't reclaim mid-game.
- `Room.ready` (set), `Room.is_public`. Actions: `set_ready`, `kick_player` (host, lobby),
  `leave_room` (lobby or game), `set_public` (host, lobby). Host transfer on lobby leave.
- `start_game` requires every non-host player to be ready.
- Lobby broadcasts become a `lobby_update` message carrying players, ready, host, public.
- `GET /api/rooms` lists public, unstarted rooms.
- Kicked or left clients get `{"type":"left_room"}` and the server closes the socket.
- Game over with left players: they're listed last and marked `left`.

**Frontend**
- Store: `lobbyReady`, `lobbyHost`, `isPublic`. `useWebSocket` handles `lobby_update`,
  `left_room` and the `name_taken` error (stop reconnecting, reset, go to `/`). Add an
  intentional-close flag so `disconnect()` doesn't auto-reconnect.
- Lobby: per-player ready badges, a Ready toggle, kick buttons and a Public toggle for the
  host, a Leave button. Start disabled until all are ready.
- Game: an Exit button in `DayRoundIndicator` with a strong confirm modal (type-to-confirm or
  hold) that sends `leave_room`. Left players show as dimmed "Left" on the boards.
- Landing page: a public-rooms list polled every 5s; picking one fills the room code.
